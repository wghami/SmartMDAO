# SmartMDAO 1.30.0: the sweep (R3)

Your cost note made this possible. The seventh request has shipped: **campaigns**, built from your
numbers and your list of needs. This completes Phase 6. Design record 006 has the reasoning.

**To upgrade:** pin `smartmdao>=1.30.0` in your project's `.venv` (campaign workers need it
there), update the MCP server, and start a new session.

## What you asked for, and where it is

| Your need | In 1.30.0 |
|---|---|
| Points built by your own code, never hand-copied JSON | `inputs_from="leo_multicast.baseline:inputs"`. A point's values become the function's keyword arguments, called inside the worker, so arrays never cross JSON. Name the grid keys after its parameters. |
| Parallelism over independent realizations and slots | A pool of workers in your project's environment (CPUs minus one by default, `workers=` to choose). Make a realization a seed, and a slot a grid value, and they run in parallel. |
| A resumable store per point | `<store>/points.jsonl`: each finished point is flushed to disk before the next starts. After a budget, a stop, a closed session or a killed process, start again and **only the missing points run**. |
| Seeds as inputs | `seeds=range(100), seed_input="seed"`. A seed no step reads is refused. |
| Per-point failure records | Every point ends `ok`, `not_converged`, `error`, `timed_out` or `crashed`, with the message. For a solver that mis-reports infeasibility or answers "inaccurate", raise in the discipline: it becomes an `error` point, kept and counted. |
| A cost quote from one point first | The default. One point is measured and the campaign estimated; starting then needs a `budget_seconds`, with no default. |

**Aggregates** group points that differ only by seed: n, mean, standard deviation and a 95 %
Student-t interval per output, with the excluded points counted beside them, never silently
dropped.

**An edited model starts afresh.** A point's key includes a hash of your source (the entry file,
the modules it imports from your project, and the `inputs_from` module) and of the SmartMDAO
version. Old points are set aside, never averaged with new ones.

## Over MCP

```
sweep_pipeline(path, store="campaigns/fig9", grid={"constellation": [...], "scenario": [...]},
               seeds=100, seed_input="seed", outputs=["latency_ms"],
               inputs_from="leo_multicast.baseline:inputs")                  -> the quote
sweep_pipeline(..., start=True, budget_seconds=18000)                        -> starts, returns at once
sweep_status(store="campaigns/fig9")                                         -> progress, failures, aggregates
sweep_stop(store="campaigns/fig9")                                           -> stops; start again to resume
```

`seeds=100` means 100 realizations. A campaign started this way runs in its own process and
survives the session. Keep `outputs` to what you report: only the steps those outputs need run,
and recorded outputs must be JSON (numbers, strings, lists of up to 10,000 elements). Reduce a
large array in a step (a mean, a percentile) and record that.
